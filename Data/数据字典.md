## 6. 无扰动理想收割进度

### `Et_2021_1.csv`、`Et_2022_1.csv`、`Et_2023_1.csv`

记录通过既有算法估计的城市在无扰动条件下的理想累计收割进度。`Et` 是模型或算法计算结果，不是观测值，因此命名时不得使用 `observed_Et`。部分值可能大于 1，当前最大值约为 1.5，这是既有算法输出，不应自动截断为 1。

| 字段名       | 代表含义                        | 数据类型 | 单位 | 数据粒度 | 是否允许缺失 | 缺失含义                  | 备注          |
| ------------ | ------------------------------- | -------- | ---- | -------- | ------------ | ------------------------- | ------------- |
| `city`       | 城市名称                        | 字符串   | 无   | 城市     | 否           | 不适用                    | 固定 81 城    |
| `YYYY-MM-DD` | 当日无扰动理想累计收割进度 `Et` | 数值     | 比例 | 城市日   | 是           | 该城市对应的 `Et`无法获取 | 不得以 0 填补 |

## 8. 城市日降水

降水数据按三种计算口径和白天、夜间两个时段分别保存。三种口径都属于对基础降水数据的汇总或换算结果，不应统一称为“直接观测降水”。项目约定数值单位按毫米（mm）记录，但总和口径与归一化口径是构造指标，解释时必须注明计算方式。

### 8.1 文件组

| 文件模式                        | 代表含义               | 计算口径                       | 单位           | 当前用途               |
| ------------------------------- | ---------------------- | ------------------------------ | -------------- | ---------------------- |
| `TotalRain_Day_YYYY.csv`        | 城市白天总降水         | 城市内所有采雨点白天降水值求和 | mm             | 备选降水口径           |
| `TotalRain_Night_YYYY.csv`      | 城市夜间总降水         | 城市内所有采雨点夜间降水值求和 | mm             | 备选降水口径           |
| `AverageRain_Day_YYYY.csv`      | 城市白天平均降水       | 白天总降水除以采雨点数量       | mm             | 备选降水口径           |
| `AverageRain_Night_YYYY.csv`    | 城市夜间平均降水       | 夜间总降水除以采雨点数量       | mm             | 备选降水口径           |
| `NormalizedRain_Day_YYYY.csv`   | 城市白天面积归一化降水 | 白天降水按区域面积归一化       | mm（项目口径） | 当前优先使用的降水口径 |
| `NormalizedRain_Night_YYYY.csv` | 城市夜间面积归一化降水 | 夜间降水按区域面积归一化       | mm（项目口径） | 当前优先使用的降水口径 |

`YYYY` 分别为 2021、2022、2023。

### 8.2 通用字段

| 字段名       | 代表含义                           | 数据类型 | 数据粒度   | 是否允许缺失 | 缺失含义                   | 备注                             |
| ------------ | ---------------------------------- | -------- | ---------- | ------------ | -------------------------- | -------------------------------- |
| `city`       | 城市名称                           | 字符串   | 城市       | 否           | 不适用                     | 固定 81 城                       |
| `YYYY-MM-DD` | 指定口径、指定时段下的城市日降水值 | 数值     | 城市日时段 | 是           | 来源文件没有该城市降水数据 | 0 表示该时段降水为 0，不表示缺失 |

### 8.3 完整日与时间窗口规则

- 完整日降水通常由同一口径下的 `Day + Night` 得到。
- 如果白天或夜间任一部分缺失，完整日降水应记为缺失，不把缺失部分当成 0。
- 当前研究常用三日窗口为“前一日 + 当日 + 后一日”的完整日归一化降水总和。
- 时间边界外没有观测日时，是否补 0、缩短窗口或设为缺失属于研究方法选择，应写入 `DECISIONS.md` 和 `Docs/研究方法.md`，不能由数据字典默认决定。

三种降水口径在 2021—2023 年均为天津市整年缺失，即每年缺失 56 个城市日；其余 80 城有值。天津市缺失不得填 0。

## 9. GNSS 田间作业轨迹

### `final_filtered_21_modified.csv`、`final_filtered_22_modified.csv`、`final_filtered_23_modified.csv`

这是已经清洗并筛去与小麦收割无关农机类型的田间作业轨迹。每行表示一台农机的一段田间作业记录，不是一个完整迁移过程。城市接续必须先按 `did` 和时间排序，再将同一农机的相邻作业阶段连接起来。

轨迹文件没有预先裁成 81 城：2021、2022、2023 年分别覆盖 213、244、261 个 `center_location` 值。保留完整覆盖是为了识别农机进入或离开 81 城的真实前后作业城市；正式网络分析时再根据研究口径筛选节点。

## 10. 农机注册地

### `农机注册地.xlsx`

记录农机平台注册地址，用于辅助区分本地作业农机和跨区作业农机。地址能否匹配到研究城市取决于地址文本完整性和地名解析结果；“注册地不匹配”只表示不能依据该表完成判定，不等于该农机没有注册地。

当前文件有 676,300 行、676,298 个唯一 `did`，其中 4 行涉及重复 `did`。连接轨迹前应先检查重复记录是否对应相同地址，不得直接静默保留任意一条。

| 字段名 | 代表含义         | 数据类型 | 单位 | 是否允许缺失 | 备注                                                     |
| ------ | ---------------- | -------- | ---- | ------------ | -------------------------------------------------------- |
| `地址` | 农机注册详细地址 | 字符串   | 无   | 否           | 可能包含省、市、县和乡镇村信息，需要解析后与作业城市比较 |

### 13.2 边级定义

设同一台农机当年的城市顺序中，起点访问序号为`i`，终点访问序号为`j`，且`i<j`：

- `边级 = j-i`。
- 一级边：起点与终点相邻，中间没有其他访问，跨越城市数为 0，权重为 1。
- 二级边：中间有 1 个访问，跨越城市数为 1，权重为 0.5。
- 三级边：中间有 2 个访问，跨越城市数为 2，权重为 0.25。
- N 级边：中间有 N−1 个访问，`跨越城市数=N-1`，`衰减权重=0.5^(N-1)`。

`跨越城市数`按中间访问位置的数量计算，不按唯一城市名称去重。例如序列 `A-B-A-C` 中，从第 1 位 A 到 C 是三级边，跨越 2 个访问。

## 14. SHA-256是什么

SHA-256可以简单理解为文件的“指纹”。它通常显示为一串64位字符，例如：

```text
ba07c3db48ff7f227dceac4381735802b5971ea53c2cac40acb494099a70e952
```

它在本项目中的用途很简单：

- 两个文件的SHA-256相同，说明文件内容相同。
- 文件内容只要有一点变化，SHA-256通常就会改变。
- 它可以帮助判断文件是否被修改、传输后是否损坏，以及本次输出是否与上次完全相同。

SHA-256不能说明数据质量好不好，也不能证明研究结论正确。它只负责回答“这两个文件的内容是不是完全一样”。

`Data/data_manifest.csv`记录了各数据文件的SHA-256；`Results/00_数据审计/城市接续审计.csv`记录了本次运行使用的输入和生成的输出文件指纹。
