用户一次性授权的GNSS标记删除已经完成。当前正式GNSS和第一步候选接续、边统计、回流路径、冲突检查及城市工时均为删除后版本。第二步、第二步原行查看及依赖第二步的接续间隔统计本次未重跑，其旧数据保留且清单标为“历史结果”，不能作为新版正式输入。完整数量及归档位置见第一步说明第13节。

## 当前数据流

```text

  → 步骤01：完整城市顺序与候选接续（Data/03）
      ├→ 第一步补充统计：未筛选候选接续的图表与回流路径
      └→ 步骤02：删除负时间间隔或起终点相同的接续行

```

两类边筛选于2026-10-20按用户要求放在第二步完成，本次仍不迁移到第一步。第一步按人工删行后的原数据重建完整顺序；未来第二步筛选仍应保留这套新顺序，不因删边而压缩、重编号或重新拼接路径。不能沿用删除前的访问编号与源行号去定位新版数据。

## 运行与检查

1. 如果第一步正式接续已经存在且与清单相符，只需运行第二步Notebook，不必重跑第一步。
2. 第二步先核对输入正式状态、行数、文件大小和文件指纹，再筛选、汇总和检查，最后输出。
3. 文件核对、分年数量及权重检查记录在`Results/01_链路数据检查/链路数据检查.csv`；阅读版汇总见第二步说明第6节。DECISIONS只保留方法决定，不保存文件实查结果。
4. 第二步Notebook自动更新本步骤九份数据及两份检查CSV在数据清单中的行数、大小、文件指纹和上下游。
5. 默认拒绝覆盖已有输出；确认重跑时开启`CITY_LINK_ALLOW_OVERWRITE=1`或参数`ALLOW_OVERWRITE=True`。按用户要求，第二步普通重跑不自动归档；此次代码修改前的备份单独登记在`Archive/README.md`。

## 上游变化后怎样重跑

- GNSS输入、城市空值规则、排序、连续同城合并、原边级或衰减权重公式变化：重跑第一步及依赖它的后续步骤。
- 第一阶段候选接续或81城名单变化：重跑第一步补充统计及第二步。
- 仅第二步两类删除或汇总规则变化：重跑第二步及已存在的下游步骤，不自动修改第一步。
- 仅图表样式变化、数值不变：只重跑对应绘图步骤。
- 第一阶段主处理及边统计的普通重跑已取消自动备份。本次用户明确要求的旧生成内容统一归档一次；调试或普通重跑不再生成额外副本。

## 第二步时间冲突原行查看

`接续删除记录.csv`中负时间间隔的边 + 对应年度第一步候选接续 + 只读GNSS → `Code/02_构建链路数据/export_time_conflict_rows.ipynb` → `Results/01_链路数据检查/时间冲突原始记录.csv`。

该查看文件仅展示逐条对应关系，不向筛选接续、城市链路或后续基线链路回写；不改变原数据及已生成的链路结果。字段说明见数据字典第17.4节。

## 第一步时间冲突完整轨迹查看

三份第一步候选接续（重算负间隔）+冲突年份的只读GNSS → `Code/01_轨迹转城市接续/export_conflict_trajectories.ipynb` → `Results/00_数据审计/冲突轨迹与GNSS.md`。

有冲突时按年份、农机、链段分段，先放完整路径，再放连续同城访问六列汇总；离开再返回同城另列。当前无冲突，Markdown显示三年检查说明，另存`时间冲突检查.csv`。用户标记原件已归档，旧四份CSV仅作删除前历史追溯，生成版本仍指向其原备份；源行号不再对应新版GNSS。查看结果不是后续链路输入，详见数据字典第19、21节。

## 接续间隔天数统计

三份`Data/04_城市链路数据/年度筛选接续.csv` → `Code/01_轨迹转城市接续/analyze_succession_days.ipynb` → `Results/00_数据审计/接续间隔统计.csv`、`三年接续间隔统计.csv`、`接续间隔分位数.csv`及四张全部接续PNG；另输出`分级接续间隔统计.csv`、`分级接续间隔分位数.csv`与八张一级、多级分类PNG。两类各有三个年份和三年合计图；共十二张PNG均标P10—P90。

该独立统计代码按用户要求放在第一步文件夹，但依赖已完成的第二步筛选接续。只输出分年和三年合计分布及分位数，不回写上游或链路数据，不用于自行选择新的筛选阈值。三年合计为记录合并，不生成跨年接续。
